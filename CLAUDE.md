# CLAUDE.md

Guía para Claude Code en este repositorio. Aquí viven SOLO invariantes: reglas que cambian el comportamiento de sesiones futuras y no son derivables del código. El historial vive en el Changelog — Portafolio D (Notion) y en `docs/platform/incident-log.md`, no aquí.

## 0 · Archivo canónico, relevo entre agentes y acceso MCP

Reglas de convivencia para los agentes de código de este repo (Claude Code y Codex). Fuente de estas reglas: "Contrato LUNA · Portafolio D" en la Diego Maury WIKI.

- **`CLAUDE.md` es el archivo canónico de instrucciones de este repositorio.** `AGENTS.md` contiene solo un puntero que manda leer este archivo completo. Si algo en `AGENTS.md` contradice o excede a `CLAUDE.md`, gana `CLAUDE.md` y se reporta como divergencia antes de modificar nada.
- **Relevo entre agentes (tokens agotados):** si estás por quedarte sin tokens o por cerrar la sesión, escribe o sobrescribe `HANDOFF.md` en la raíz del repo con: fecha, agente saliente, tarea o fase actual, trabajo completado, trabajo a medias (archivo:línea), siguiente paso y payloads del Inbox pendientes de registrar. Al iniciar, cualquier agente lee `HANDOFF.md` si existe y retoma desde ahí. `HANDOFF.md` es efímero: se sobrescribe en cada sesión; el historial permanente vive en el Inbox y en Changelog — Portafolio D.
- **Sin acceso MCP a Notion:** el agente entrega los payloads JSON completos en su respuesta final y Diego o SILVIA los registran en el Inbox con las mismas propiedades (`Estado de procesamiento = Pendiente`). La falta de acceso MCP no exime el registro.

### Tooling
- CI/deploy real: Cloudflare Pages (Git integration, build de Astro en su propio entorno). `.github/workflows/deploy.yml.disabled` es el pipeline anterior (GitHub Actions → GitHub Pages), conservado solo como referencia; no corre. `npm ci --omit=dev` (puppeteer/Chromium no se instala en CI).

Su único consumidor es `src/styles/ds-tokens-drift.test.ts` (`npm test`), que compara por valor literal los 9 colores compartidos + `--border-control` (D-B) contra `variables.css`, y solo la familia PRIMARIA (no la cadena completa) de `--display/--sans/--mono` — el valor completo diverge a propósito porque el sitio autohospeda con fallback propio encadenado. Para actualizar tras un cambio real en el DS: repetir `DesignSync get_file` sobre `v2-tokens.css`/`v2-dimensions.css` y reemplazar el vendoreado entero. **`parseTokens` debe despojar comentarios `/* ... */` antes de buscar declaraciones `--token: valor;`** — un comentario de prosa que mencione un token puede matchear como si fuera la declaración real. `--ember-fill`/`--ember-fill-strong` — relleno de estado en Ember, nunca texto ni borde.
- `test:a11y:astro`/`verify:visual:astro` son la ÚNICA ruta de QA visual/a11y. `npm run lint` es solo `htmlhint public/404.html`.
- `qa-output/screenshots-astro/` es regenerable (gitignored) — nunca se versiona.
- `verify:visual:astro` (Playwright `fullPage` screenshot) puede capturar secciones en negro/vacío por debajo del hero: es el efecto esperado de `[data-reveal]` (`opacity:0` hasta que el `IntersectionObserver` dispara `.is-visible` por scroll real, no por el auto-scroll interno de Playwright al hacer stitching). Para verificar visualmente contenido nuevo, usar el navegador real (Claude-in-Chrome) con scroll físico, no confiar en el PNG de `verify:visual:astro` para secciones bajo el fold.
- `test:a11y:astro`/`verify:visual:astro`: config `playwright.astro.config.ts` (arranca `astro preview` en el puerto 4322, requiere `astro build` previo), specs `tests/qa/a11y.astro.spec.ts`/`visual.astro.spec.ts`, lista de páginas en `tests/qa/pages.astro.ts` (`ASTRO_QA_PAGES`). Cualquier página nueva bajo `src/pages/*.astro` se registra aquí.
- **Gotcha del `webServer` de Playwright:** `astro preview` (Astro 7) se demoniza — el proceso que lo lanza sale con exit 0 de inmediato, así que el `webServer` que spawnea Playwright "muere" y la suite aborta sin correr un solo test. Workaround: `npx astro preview --port 4322` a mano en background (verificar `curl` 200), luego `npm run test:a11y:astro` aparte. Al terminar: `npx astro preview stop` (puede haber daemons huérfanos ocupando el 4322 — detectar con `Get-NetTCPConnection -LocalPort 4322`).
- **Gotcha de `astro build` exit 0 engañoso:** un timeout del loader de Notion durante la carga de contenido puede abortar el build dejando exit 0 y `dist/` sin regenerar. Antes de dar un build por bueno o desplegar desde `dist/` local: confirmar que el log termina con `[build] Complete!` / `N page(s) built`, o comparar el mtime de un archivo de `dist/` contra "ahora". No basta el exit code (reintento máx. 2 suele completar). Causa frecuente en local: DeepL inalcanzable (`Connect Timeout` a `api-free.deepl.com`) mata el build en silencio con exit 0; workaround de QA local: `DEEPL_API_KEY="" npx astro build` (omite traducción con warning y el cache versionado no se modifica) — nunca para un build que se despliega.
- **Verificación en navegador real cuando Claude-in-Chrome no está:** la ruta válida NO es un chequeo HTTP — es un script de Playwright local (`playwright` 1.61.1, correrlo desde la raíz del repo o desde un path bajo `qa-output/lighthouse-baseline/` gitignored, no desde scratchpad). Da Chromium real + viewport móvil (`devices['Pixel 5']`) + throttling CDP + `PerformanceObserver` de `layout-shift`.
- **Las páginas Astro estáticas (sin loader, ej. `docencia.astro`) no pueden embeber directamente las fotos/videos de evidencia de un caso del CMS**: esas imágenes viven en `public/cms-media/notion/`, pobladas únicamente por el loader dinámico en build time. Una página estática nueva que quiera mostrar esa evidencia debe enlazar a la ficha ya publicada (`/portfolio/{slug}`), no fabricar rutas de imagen.
- **Verificación visual obligatoria tras cambios de layout/CSS:** ningún cambio de layout o CSS se da por terminado solo con `astro build` en verde o un HTTP 200 del deploy — se verifica en Chrome real (Claude-in-Chrome) a 1440px y 390px, revisando explícitamente los patrones de bug ya conocidos: navbar `fixed` tapando contenido nuevo sin offset (§4); contenedores con `container-type` + hijos 100% `position:absolute` colapsando a ancho/alto 0 (§4); y JS que hace `el.hidden = true` en una hoja de estilos que NO declara `[hidden]{display:none!important}` (cualquier `display` de author gana al `[hidden]` del user-agent). Toda hoja `src/styles/*.css` de una página que use `el.hidden` debe incluir esa regla. Si Claude-in-Chrome no está disponible o se desconecta a medio camino, la verificación se declara BLOQUEADA explícitamente — nunca se sustituye en silencio por un chequeo de status HTTP. `mcp__claude-in-chrome__resize_window` NO reduce el viewport del documento (`window.innerWidth` se queda en 1440) — para verificar 390px sin Playwright, forzar el ancho con JS y medir con `getBoundingClientRect`; la ruta real para responsive sigue siendo el script de Playwright local con `devices['Pixel 5']`. Un panel `position:absolute` anclado con `left:0` respecto a su trigger puede desbordar el viewport en mobile si el trigger no es el primero por la izquierda — al abrir, medir `getBoundingClientRect()` contra `window.innerWidth` y flipear el ancla a `right:0` cuando se detecta overflow, más un `max-width: min(<ancho fijo>, calc(100vw - 32px))` como tope duro.
- Archivos o carpetas con prefijo `_` (ej. `_experiment.astro`, `_draft/`) son ignorados por el router de Astro — nunca usar ese prefijo en una página que deba ser accesible. Ante un build fallido contra la API de Notion (timeout, rate limit), reintentar como máximo 2 veces con backoff — al tercer fallo, revertir el cambio que disparó el build y reportar la limitación en vez de seguir reintentando a ciegas.
- Todo dev server o build largo (`astro dev`, `astro build`, suites de Playwright) se lanza en background, nunca en foreground bloqueando la sesión — se espera la notificación de finalización en vez de programar wakeups o polling repetido.
